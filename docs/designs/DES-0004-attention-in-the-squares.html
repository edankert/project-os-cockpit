Attention in the squares

The overview's Waiting on you list exists because the phase squares cannot say that anything needs a human. Every item that list shows is already on the page as a square — measured 2026-07-30: 9 of 9 rows, 8 visible. All nine render as plain hollow squares, pixel-identical to work nobody has started.

So the list is not a second view. It is a workaround for an under-expressive encoding. This design gives the square the states it is missing, so the list can go.

Today the square has exactly two states — filled for the done bucket, hollow for everything else — plus type colour. The payload computes a third bucket, in_progress, and the stylesheet has no rule for it. Status otherwise lives only in the title tooltip, which a tablet cannot reach.

The proposed encoding

Five marks. Colour stays on type throughout — it is spent, and the type legend is used across six surfaces.

MarkMeansMembers
Delivered done band — done, fixed, implemented, merged, passing, resolved, closed, complete, released, published, verified, fulfilled, met
Resolved, nothing delivered archived band — cancelled, superseded, retired, obsolete, deprecated, declined, reverted. Solid, because it is settled and its parent can close over it; the slit withdraws the delivered claim.
Parked, still wanted deferred — hollow, because it is neither built nor terminal and its parent cannot close over it.
In progress
pulsing		 doing, active, in-progress
Complete, unproven
static		 terminal under a recorded verification_waiver, or a manual test passing on a stale last_verified
Outstanding human action triage, review, ready tests, and computed-blocked (an unresolved depends:)
Not started backlog, open, draft — nothing is wrong and nobody is waiting

The dot composes with every fill state; the others are exclusive. That is not a convenience — STATUSES.md says "an item can be blocked while still doing, which a status cannot express", so the two must be able to coexist on one square. Precedence among the fills: dropped wins over delivered and unproven, because an abandoned item was never built.

The dot on top of each fill

Six squares, each fill state with and without the dot, at 1:1 and again at 3× so the geometry is checkable.

The dot sits outside the square's top-right corner with a 1px --bg ring, so it never occludes the fill it is layered over and stays legible against a solid one.

Struck out, twice — and the fill is what separates them

Two states share the diagonal gesture because they mean nearly the same thing: deliberately not being done. What differs is whether it is settled, and fill carries exactly that.

The pairing is what makes this work: one gesture for "deliberately not done", and the fill — the strip's primary signal — distinguishes settled from parked. Reversing them would have been wrong in a way worth recording: a filled square for deferred would put weight behind work that is not built and still blocks its parent from closing.

Population: 6 archived and 2 deferred of 373 (TASK-0045, TASK-0065). Both rare, which is why they can afford a mark that reads as damage.

Tests join the squares

Tests are not in the phase payload today — the strip carries features, tasks, requirements and issues only (measured: 50 / 244 / 25 / 54 = 373). Giving ready tests a dot therefore requires adding the type, which is a sidecar change, not CSS.

It is worth doing on its own merits: 20 of 22 tests carry a phase:, so they slot in. And it is where unproven earns its keep — all 22 tests read passing, 21 are manual, and 9 were last verified 66–83 days ago. Today they would all be solid squares.

“close out” — every item done, phase not closed. A property of the phase, so no square can hold it, and the only row in the current list that nothing else on the page can tell you.

“3 waiting” — a collapsed phase renders its squares with offsetParent: null; ISS-0024's square is on the page and invisible. Without this count the change loses information the list shows today. Count only, no ids — a header listing ids would be Waiting-on-you with extra steps.

The quiet state, which is the common one

Nothing waiting, nothing dropped, nothing unproven: the strip is exactly what it is today and the overview loses a section that said All clear. Quieter rather than more informative is the intent, and what REQ-0022 asked for.

Alternatives that lost

Inverted fill for “needs a human”

The first draft's treatment A. Rejected: it competes with the solid done fill at 9px, and it is needed for a state that genuinely reads as "filled but qualified" — which attention does not.

Dim everything that is not attention

Strongest at a glance and rejected anyway: it re-purposes the strip as an attention view, degrading the progress reading it exists for.

Counts and pointers instead of the squares

Keep the section, reduce it to “3 open issues →”. Rejected: the stat tiles two sections above already are that indication, so it would have been a third rendering of the same number.

review on a fill rather than the dot

Rejected: review is an outstanding human decision, so splitting it from triage would put one concept on two channels.

A dot for open and deferred

Rejected by the owner, and correctly: open is accepted work waiting on capacity, and deferred is a decision already taken — STATUSES.md calls it "explicitly out of the current parent's scope". Neither is waiting on anyone.
