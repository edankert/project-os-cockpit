# A Codex session in the cockpit has not been walked end to end, and its cache badge says 'cache unknown'

Codex now reports its prompts, approvals and finished turns to the cockpit, but nobody has yet watched one full Codex session go through every state on screen. The session strip also shows 'cache unknown' for Codex, because the cockpit has no source for Codex's cache data.

## Problem

The cockpit launches Codex and receives its `notify` callback, but it does not receive the prompt and tool events that keep a Claude session's state and activity strip current. The repository also gives Claude generated hooks, skills, and subagents while its Codex adapter still describes repository scripts as substitutes for native hooks. Native Codex hooks are now available, so the delivered behavior and the recorded plan need a new implementation and a live check.

## Original repro

1. Compare the `claude` and `codex` shell functions generated by `desktop/src/ipc/agent-instrument.ts`. Claude loads a settings file with ten lifecycle hooks and a statusline command; Codex receives only `-c notify=[...]`.
2. Complete one Codex turn and start another in the embedded terminal. The `agent-turn-complete` callback can set the cockpit state to `waiting`, but the new prompt sends no `UserPromptSubmit` event to set it to `busy`.
3. Inspect `tools/adapters/codex/ADAPTER.md` and the repository root. The adapter describes script entrypoints, and there is no project `.codex/hooks.json`, generated `.agents/skills/`, or Codex custom agent configuration.
4. Compare `docs/features/agent-hooks/plan/tasks/TASK-0116-Codex-Hook-Injection.md` with `desktop/src/ipc/agent-instrument.ts` and the Codex row of `TST-0011`. The checked lifecycle-hook and live-verification claims exceed the delivered `notify` wrapper; the live Codex check was skipped.

## Expected

A Codex session should report prompt start, work, permission requests, turn completion, and session end through the same cockpit state vocabulary used for Claude. Project-os lifecycle checks and playbooks should also be available through Codex's native hooks and skills, with their own tool-specific input and output adapters.

## Actual before this change

`codex-notify.sh` maps payload text containing `agent-turn-complete` to `Stop` and `approval-requested` to `PermissionRequest`; all other notifications become `Notification`. It does not send `SessionStart`, `UserPromptSubmit`, tool activity, `SessionEnd`, or statusline data. The approval mapping has a synthetic endpoint test, but no live Codex acceptance result. The dispatch queue uses the latest agent state when deciding whether to queue or type a prompt, so a stale `waiting` state can affect delivery while Codex is working.

The project icon and Needs you card read one stored agent state per workspace. A post-restart sidecar snapshot on 2026-09-16 showed a live Codex session while the workspace state still named Claude as waiting. The renderer treats a waiting state older than one hour as cold, paints the icon grey, and removes that agent event from Needs you. This age rule assumes Claude's prompt-cache lifetime and its tooltip claims that resuming rewrites cached tokens. It is not evidence of Codex cache temperature. The detailed cache badge is absent because `session_cache.py` reads Claude transcript fields and the Codex notify payload has no transcript path or cache usage.

OpenAI also documents repository skills under [`.agents/skills`](https://learn.chatgpt.com/docs/build-skills) and project [custom subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) under `.codex/agents/`.

`src/project_os_cockpit/agent_hooks.py` already understands the lifecycle event names. Its touched-file path assumes `tool_input.file_path` or `tool_input.path`, while Codex sends `tool_input.command` for `apply_patch`. Codex tool events therefore need a separate file-path mapping before the cockpit can claim file activity parity. Claude's statusline supplies cost and context fields; native Codex hooks do not establish an equivalent feed in this review. The [Codex App Server](https://learn.chatgpt.com/docs/app-server) exposes turn, item, approval, and token-usage events if richer data or confirmed dispatch becomes a later requirement.
